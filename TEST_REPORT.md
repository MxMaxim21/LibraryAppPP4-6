# Отчёт о тестировании LibraryApp

## Объект тестирования

**LibraryApp** — консольное приложение на C# (.NET Framework 4.8) для учёта книг в библиотеке.
Приложение позволяет добавлять книги, выдавать их читателям, принимать обратно и искать книгу по идентификатору.

Состав приложения:

| Класс | Назначение |
|---|---|
| `Book` | Описание книги: `Id`, `Title`, `Author`, `IsAvailable` (по умолчанию `true`) |
| `Library` | Хранит список книг; методы `AddBook`, `BorrowBook`, `ReturnBook`, `FindBook` |
| `Program` | Точка входа `Main`: создаёт библиотеку и демонстрирует операции |

## Методика тестирования

1. **Ручное тестирование.** Запуск приложения с набором позитивных и негативных сценариев в `Main`:
   выдача и возврат существующей книги, выдача несуществующей книги, повторная выдача, возврат невыданной книги, добавление `null`.
2. **Отладка в Visual Studio.** Точки останова в `BorrowBook`, `ReturnBook` и `FindBook`; пошаговое выполнение (F10, F11);
   контроль значений в окнах «Локальные» (Locals) и «Контрольные значения» (Watch): `id`, `book`, `book.IsAvaible`, `books.Count`.
3. **Статический анализ.** Сборка проекта с просмотром окна «Список ошибок» (Error List).
4. **Ручная инспекция кода** по чек-листу: стандарты именования (PascalCase / camelCase), наличие XML-документации,
   длина и ответственность методов, обработка исключений (пустые `catch`, перехват всех исключений подряд).

Отладка выполнялась на первой версии проекта (коммит `release class book`), где граничные случаи намеренно не обрабатывались.

## Результаты инспекции кода

Статический анализ: в окне «Список ошибок» до и после исправлений **0 ошибок и 0 предупреждений**.
Это объясняется тем, что при настройках по умолчанию (проект .NET Framework 4.8) компилятор не контролирует именование,
наличие XML-документации и неиспользуемые директивы `using`, поэтому замечания выявлены ручной инспекцией.

| № | Замечание | Где | Исправление |
|---|---|---|---|
| 1 | Опечатка в имени свойства: `IsAvaible` вместо `IsAvailable` (требование задания) | `Book` | Свойство переименовано |
| 2 | Нарушение стандарта именования: локальная переменная `Library` в PascalCase | `Main` | Переименована в `library` |
| 3 | Нарушение принципа единственной ответственности: `Book` хранил список книг и содержал методы управления библиотекой | `Book` | Логика вынесена в отдельный класс `Library` |
| 4 | Отсутствие проверок и раннего выхода, отсутствие фигурных скобок в `if/else` | `BorrowBook`, `ReturnBook` | Добавлены проверки `null` и `IsAvailable`, `return`, явные скобки |
| 5 | Некорректная обработка исключительной ситуации при `AddBook(null)` | `AddBook`, `Main` | Генерируется `ArgumentNullException`; в `Main` перехватывается конкретным `catch` |
| 6 | Отсутствие XML-документации у публичных типов и членов | `Book`, `Library` | Добавлены `/// <summary>`, `<param>`, `<returns>`, `<exception>` |
| 7 | Неиспользуемые `using`, опечатки в комментариях, результат `FindBook` не выводился | `Book.cs`, `Program.cs` | Лишнее удалено, комментарии исправлены, результат поиска выводится |

Проверка обработки исключений: пустых блоков `catch` и перехвата всех исключений подряд не обнаружено,
используется один конкретный `catch (ArgumentNullException)`.
Проверка длины методов: каждый метод короткий и выполняет одну задачу, дополнительный рефакторинг не потребовался.
Небольшое дублирование блока «поиск книги и проверка на `null`» в `BorrowBook` и `ReturnBook` признано допустимым для данного объёма кода.

## Итоги

**Повторное тестирование после исправлений** (те же сценарии и точки останова):

| Сценарий | Результат |
|---|---|
| `BorrowBook(1)` для доступной книги | Книга выдана, `IsAvailable = false` |
| `ReturnBook(2)` для выданной книги | Книга возвращена, `IsAvailable = true` |
| `FindBook(3)` | Книга найдена, название выведено |
| `BorrowBook(4)` — книги нет | Сообщение «книга не найдена», исключения нет |
| `BorrowBook(1)` повторно | Отказ, присваивание `IsAvailable` не выполняется |
| `ReturnBook(3)` — книга не выдавалась | Сообщение «уже в библиотеке», присваивание не выполняется |
| `AddBook(null)` | `ArgumentNullException` перехвачен, список не изменён |

**Выводы.** Все пять найденных дефектов устранены. Код стал соответствовать стандартам именования,
публичные члены документированы, граничные случаи обрабатываются явно, исключения не скрываются.
